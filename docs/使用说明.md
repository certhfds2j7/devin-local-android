# 中文使用说明

## 初始化

安装来源一致的 Termux 主应用和扩展。首次打开 Termux 后完成基础软件包初始化，再按客户端“首次连接”中的说明开启应用连接。该开关允许持有 Termux 专用权限的应用请求执行命令；只向你信任的客户端授予该权限。

点击“连接环境”后，会建立 Ubuntu 24.04 ARM64 环境并安装官方 CLI、Python、Node 24 LTS 和 Git。第一次可能需要数百 MB 下载及数 GB 可用空间。不要清除 Termux 数据。已有实机验证环境 `devin-android-gate` 会复用，保留官方登录。

若连接失败，先确认 Termux 已打开、连接设置已生效、客户端获得了 Termux 的“执行命令”权限。初始化诊断保存在 Termux 的 `~/.local/share/devin-local-android/bootstrap.log`；不要公开包含官方登录内容的终端截图或文件。

一加 / ColorOS 需要另外检查“设置 → 应用 → Termux → 耗电管理”，选择“完全允许后台行为”。仅通过 Android 标准的电池优化确认框，在目标手机上仍会被厂商策略暂停。本次安装已按机主授权完成这项设置。保持后台运行可能增加耗电；结束编程后可自行停止 Termux，使用时再启动。

## 登录

设置中点“官方账号登录”，在 Termux 中按官方提示进行手动登录。浏览器登录曾出现服务器 500，使用官方手动令牌流程已在目标手机成功。不要把令牌、密码或登录链接发送到聊天或写入公开仓库。

AI 回答需要手机联网；断网时文件编辑、Git 本地操作和已有工具仍可使用，AI 请求应等待网络恢复。账号额度和可选模型以官方返回结果为准。

## 完成一个 Python 项目

1. 新建“Python 项目”，开始对话，例如“用中文解释，为这个项目添加一个计算器，并在本地运行测试”。
2. 收到工具权限请求时检查文件路径和命令，选择“仅允许这一次”或拒绝。未批准的请求不会由客户端自动允许。
3. 在“编辑”查看文件，在“项目 → Git 与修改对比”检查差异。
4. 打开终端运行 `python3 main.py`。需要依赖时建议使用虚拟环境：

   ```sh
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install 所需包名
   ```

5. 在 Git 对话框设置当前项目提交身份，暂存后填写说明并提交。

## 网站项目

创建网站模板后，可让代理扩展 HTML / CSS / JavaScript，或在空项目中建立 Node / TypeScript 项目。在终端运行开发服务器，并在手机浏览器打开终端显示的 `http://127.0.0.1:端口`。服务器使用手机本地文件；请按任务需要决定是否对局域网开放，本客户端不会自动开放外部监听。

## 文件与 Git

编辑器默认保存草稿，点击“保存”才写入项目。若出现文件版本冲突提示，先保留草稿、检查 Git 差异，再决定重新载入。代理处理当前项目时编辑器写入被暂时禁止。

已有代码可导入空项目 ZIP，或把 HTTPS / SSH 地址克隆进空项目。Git 认证在终端配置，客户端不会收集 Git 密码。新文件应先暂存，随后在差异中检查。导出 ZIP 会跳过 Git 目录及符号链接；不要把包含私有代码或凭据的 ZIP 公开上传。

## 后台与恢复

任务运行时保留 Termux 和本客户端的后台运行权限，并允许通知。切回客户端后可重新连接对话或从历史会话恢复。Android 仍可能回收进程，通知并不能保证永不被终止。

代理或桥接进程已结束时，会显示中断；历史文字仍保留。官方代理支持 `session/load` 时恢复原会话；不支持时保留历史并提示新建对话。不会假装未完成的任务已经成功。

## 更新与备份

“检查应用更新”或“导入新版 APK”更新中文界面和本地服务。安装需系统确认；错误签名、包名或旧版本会被拒绝。“更新 Devin 核心”独立更新官方代理；请结束任务并关闭终端。升级失败时继续使用原核心。

APK 更新后再次点击“启动 / 重新连接”，本地服务会在空闲时切换。项目、账号与私有配置独立保存。签名备份属于维护者的发布凭据，普通使用无需导入密钥；不要卸载应用来规避签名不一致提示。
