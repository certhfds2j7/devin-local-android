# 更新、签名与发布

## 使用者如何更新

客户端检查 `certhfds2j7/devin-local-android` 的最新正式 GitHub Release 中的 `update.json`。启动时按每日缓存检查，也可在设置手动检查。下载完成后核对 SHA-256、包名、递增版本号及与当前安装相同的签名，最后由 Android 系统确认安装。每日检查仅提醒，不静默安装。也可导入可信渠道下载的新版 APK；离线导入核对版本、包名和签名。

下载失败的临时文件会清理，可重试下载。若版本、签名或兼容性检查失败，不应卸载旧版绕过。APK 更新后点“重新连接”同步桥接；如有任务或终端在运行，先完成或关闭。

官方代理有单独的更新入口。从官方 `static.devin.ai` 获取清单及 ARM64 发行文件，核对摘要，先在候选版本完成 ACP v1 握手再切换 `current`。保留此前核心及私有配置快照。失败时恢复原核心和原配置，新版本产生的迁移文件留在私有备份供排查。更新不把任务改为云端执行。

## 签名密钥

首次正式 APK 采用固定 RSA 发布密钥。后续版本必须使用相同密钥；本项目尚未实现签名轮换，不要重新生成临时密钥。

维护者应离线备份 `devin-local-release.p12`、别名及密码。密钥文件与密码属于私密发布凭据，禁止上传到公开仓库、Release 或工单。建议把密码与密钥分开保存。丢失密钥将无法覆盖升级现有安装。

公开证书摘要位于 `docs/release-signing-cert.sha256`，不包含私钥。本地正式构建设置以下环境变量，再运行 `./gradlew :app:assembleRelease :app:lintRelease`：

- `DEVIN_STORE_FILE`：私有 p12 文件的绝对路径。
- `DEVIN_STORE_PASSWORD`：密钥库密码。
- `DEVIN_KEY_ALIAS`：`devinlocal`。
- `DEVIN_KEY_PASSWORD`：私钥密码。

构建前重新生成网页资源和 `python3 tools/bundle-runtime.py`；桥接、初始化逻辑和 Node 发行摘要共同计入运行包摘要。

## GitHub Actions

CI 运行桥接测试、构建与 Lint，保存调试 APK 供排查。标签发布流程要求维护者配置 Repository Actions Secrets：

- `DEVIN_KEYSTORE_BASE64`：p12 文件的 Base64。
- `DEVIN_STORE_PASSWORD`。
- `DEVIN_KEY_PASSWORD`。

别名固定为 `devinlocal`。Secrets 由 GitHub 加密保存，不进入源码。外来 Pull Request 不接触签名凭据；发布只由本仓库版本标签触发。

1. 更新 `app/build.gradle.kts` 的 `versionName` 和递增的 `versionCode`。
2. 更新 `docs/acceptance.md`、`docs/release-notes.md` 和中文说明，完成实机检查。
3. 提交并推送一致的版本标签，例如 `v0.1.0`。
4. 工作流验证正式证书、生成 `update.json` 与摘要，创建**草稿 Release**。
5. 维护者核对附件及验收结果后公开发布。只有最新正式 Release 会被客户端发现；预发布版与草稿不作为日常正式更新。

工作流已准备不代表仓库 Secrets 已配置。缺失时预检会明确跳过云端签名发布，不会生成另一把签名密钥。维护者也可在本地完成签名和校验，将 APK、`update.json`、摘要及中文说明上传到正式 Release；无需把私钥交给 GitHub。

当前公开仓库为 [certhfds2j7/devin-local-android](https://github.com/certhfds2j7/devin-local-android)。本次首次发布采用已在手机安装验证的本地签名包，私钥继续保留在维护者本地；未配置 GitHub 签名 Secrets。

## 本地恢复

账号与官方会话留在 Ubuntu 内，项目与桥接历史位于 Termux 私有目录。卸载 Termux 会清除这些数据，APK 更新不会清除。重要项目请自行导出。

更新失败快照在 `~/.local/share/devin-local-android/backups`，可能包含官方账号配置，禁止公开。若原核心也无法工作，保留诊断并按官方流程重新登录或恢复，不降低权限策略。
